# FinanceAI (Tijori AI) — Exhaustive System Audit Report
**Date:** May 6, 2026
**Status:** 🛠️ Audit Complete

---

## 📊 Executive Summary
The FinanceAI platform is partially functional but suffers from significant architectural drift between the legacy HTML/JS frontend and the new unified shell. Key backend APIs are stable, but several critical UI modules are either missing (404), restricted incorrectly (403), or contain runtime JavaScript errors.

## 🛠️ Critical Technical Issues Identified

1.  **Database Compatibility:** Migrations contain Postgres-specific SQL (`GENERATED BY DEFAULT AS IDENTITY`) which breaks local SQLite development environments.
2.  **Broken Script References:** Several legacy pages (AP Match) attempt to use a global `AUTH` object that is no longer being initialized in the new shell.
3.  **Path Inconsistency:** There is a mismatch between the URLs generated by the backend and the actual file structure in `frontend/`.
4.  **Seed Data Gaps:** Default `seed_demo` command skips Vendor and basic Employee accounts, making it difficult to test the full lifecycle without manual intervention.

---

## 💡 Recommendations

1.  **Unified Shell Migration:** Deprecate individual `code.html` files and move all logic into the `Tijori AI.html` React-based shell.
2.  **Fix Path Mappings:** Standardize directory names in `frontend/` to match the expected URLs in `urls.py`.
3.  **Generic Migrations:** Update migrations to use Django's ORM abstractions instead of raw Postgres SQL to ensure multi-DB support.
4.  **RBAC Cleanup:** Simplify the permission model; too many 403s are frustrating for lower-grade users who need to see their own data.
