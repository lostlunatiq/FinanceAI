# Persistent Instructions for ClickHouse Migration

1. NEVER modify a file without reading it first. Use cat or read_file before any write.
2. NEVER leave TODO comments, placeholder functions, or pass statements in production code.
3. ALWAYS preserve existing functionality — add, don't replace, unless explicitly specified.
4. For Django models: always include Meta options (db_table, ordering, indexes).
5. For ClickHouse: always use IF NOT EXISTS in CREATE TABLE statements.
6. For Celery tasks: always use @shared_task with explicit name, bind=True for self-retry.
7. For API views: preserve existing permission classes and serializer structures.
8. For React: preserve existing component structure, add new props don't break old ones.
9. When in doubt, ask before implementing. Do not guess on security-critical code.
10. After every file write, verify syntax with python -m py_compile or eslint.
